## P1-#2: LLM 响应缓存（借鉴 MetaGPT + AgentScope Java）

### 方案

Caffeine LRU 缓存，在 `ModelInvoker.callWithStream()` 中透明拦截。缓存 Key = `modelName + ":" + messages.contentHashCode()`。

### 新增文件

| 文件 | 职责 |
|------|------|
| `ModelCallCache.java` | Caffeine Cache 封装（get/put/invalidate/clear） |

### 修改文件

| 文件 | 改动 |
|------|------|
| `aether-domain/pom.xml` | 添加 Caffeine 依赖 |
| `ModelInvoker.java` | 新增 `callWithStreamCached()` → 查缓存→调用→写缓存 |
| `AgentConfig.java` | 新增 `cacheEnabled` (default true) + `cacheTtlSeconds` (default 60) |

## P1-#4: PlanActAgent（借鉴 MetaGPT PLAN_AND_ACT + AutoGen MagenticOne）

### 方案

新增 `PlanActAgent implements Agent`，三阶段：Plan（LLM 生成 JSON 计划）→ Act（逐步 ReAct 子循环）→ Synthesize（合并结果）。

### 新增文件

| 文件 | 职责 |
|------|------|
| `PlanActAgent.java` | Plan-Act-Synthesize 三阶段 Agent |
| `Plan.java` | 计划模型（steps, totalSteps） |
| `StepResult.java` | 步骤执行结果 |

### 修改文件

| 文件 | 改动 |
|------|------|
| `DefaultAgentFactory.java` | case "plan_act" → new PlanActAgent(...) |
| `AgentConfig.java` | 新增 `PlanSettings` (maxSteps, autoApprove) |

### 方案

### 修改文件

| 文件 | 改动 |
|------|------|
| `ModelInvoker.java` | 新增 `callWithStreamAsync()` + 重构 `callWithStream()` 为内部调用 |
